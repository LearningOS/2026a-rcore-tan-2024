# 第六章实验报告：文件系统

## 一、实现功能总结

实现 `fstat`、`linkat` 和 `unlinkat`，支持文件状态查询、硬链接和删除。保留原有磁盘格式，通过根目录项统计链接数，在最后一个链接和打开引用均释放后回收 inode 与数据块。完善文件权限、用户指针检查和分配失败回滚，恢复时间查询、内存映射、文件系统加载的 `spawn` 及 Stride 调度，并完成综合与边界测试。

## 二、问答作业

### 1. 在我们的easy-fs中，root inode起着什么作用？如果root inode中的内容损坏了，会发生什么？

root inode 是根目录的索引节点，也是通过文件名访问其他文件的入口。创建文件系统时，easy-fs 为根目录分配编号为 0 的 inode，并将其类型初始化为目录。打开文件系统后，内核通过 `EasyFileSystem::root_inode` 取得它，并保存为 `ROOT_INODE`。

根目录的数据区存放目录项，每个目录项记录文件名和对应的 inode 编号。文件本身的数据由其 inode 管理，根目录负责建立名称到 inode 的对应关系。因此，查找、创建、列举文件，以及本次实现的硬链接和删除操作，都需要访问根目录。在当前只有根目录的文件系统中，硬链接数量也可以通过统计指向同一 inode 的有效目录项得到。

损坏不同内容会产生不同后果：

- 如果目录项中的名称损坏，文件可能无法按原名称找到；如果 inode 编号损坏，名称可能错误地指向其他文件或无效 inode。
- 如果 root inode 的大小、直接索引或间接索引损坏，目录遍历可能遗漏文件、读到错误的数据块，或者触发内核断言和异常。
- 即使文件的数据块仍然存在，丢失目录项后也可能无法通过文件名访问这些数据，形成无法正常访问的文件。

本次实现还依赖根目录统计链接数。如果根目录损坏，链接计数和回收判断也可能失真。当前实现没有日志恢复和文件系统修复工具，不能保证在这种情况下安全恢复；需要从备份恢复，或离线检查目录、inode 和分配位图的一致性。

### 4. 实验结果分析

硬链接共享 inode，因此通过任一名称写入的数据都能通过其他名称读取。删除目录项只减少名称引用；仍有其他链接时保留文件，链接数为零但仍有打开引用时也保留数据，直到最后一个打开引用释放才回收 inode 和数据块。这样能够避免提前删除打开文件以及重复回收。

本次没有改变磁盘 inode 的布局，而是利用当前只有根目录的结构统计链接数，并缓存共享的内存 inode 句柄。创建和链接会复用删除后留下的目录槽，避免重复创建、删除时持续扩张目录。磁盘分配失败时回滚本次尚未接入 inode 的块，不影响文件原有内容。

这些测试验证了当前实验覆盖范围内的正确性，不代表已经实现断电恢复、多核并发或完整的多级目录语义。
